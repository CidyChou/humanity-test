# HUMAN / 01 — 人类退化测试 V3.1

## 启动
直接用现代浏览器打开 `index.html`，或在 macOS / Linux 终端执行：

```sh
chmod +x start.sh
./start.sh
```
默认端口 8765（可传入自定义端口）。脚本打印本地和局域网地址。无外部资源、无 API Key、无需安装依赖。手机需与电脑在同一局域网。

## 评分协议 H01-P02
8 项任务保留原顺序和难度层级，每局重新随机出题。每项满分 100，原始分与独立评估分分别记录；每关一次正式结算，无准备页、无中途成绩页；完成、超时或抵达导航终点自动进入下一关，最终报告统一展示成绩和复盘。各项权重分别为 8%、10%、12%、12%、13%、13%、12%、20%。综合分为独立评估分的加权总和，保留一位小数。AI 提示后计原始分的 70%，AI 接管计 0。AI 依赖记录：提示 8、接管 20，每项只计一种，最大 100。

| 项目 | 规则 |
|---|---|
| 心算 | 每题等权，未答或错答计零 |
| 记忆 | 按输入位置逐位比较，允许部分分，不即时提示正误 |
| 导航 | 70 × max(0, 1 − 路线编辑距离/标准路线步数) + 30 × 是否到达 − 5 × 碰撞次数，限制在 0–100 |
| 编程 | 取电池35分、到达35分；成功且无碰撞时效率分为30 × 最优指令数/实际指令数，碰撞扣10 |
| 筛选 | 100 × max(0, 命中数 − 误选数)/目标数 |
| 终极关 | 20步路线、5秒观察、50秒作答；必须完全匹配且零碰撞、按时抵达才算极限挑战通过 |

S++：综合 ≥97、全部独立且极限通过；S+：≥92 同条件；S：≥85 且无 AI 接管；否则 A ≥80、B ≥65、C ≥45、D <45。等级为游戏设计阈值，不是人口常模。5% 为目标首试通过率，尚未通过真实样本验证。

本地记录存于 localStorage，V3.1 沿用 `humanity01-v2` 和 `humanity01-v2-active` 及 H01-P02 评分协议，不覆盖 V1。原存档对象新增 `deck` 保存整局题目，刷新恢复和最终复盘使用本局题目；无 `deck` 的旧记录仍使用旧题复盘。测试开始后退出或刷新，本项视为中断记0（浏览器允许 localStorage 的情况下）；已完成成绩保留。重复挑战允许提高成绩。离线版本不具备服务器签名、跨设备防作弊或真实人群排名。成绩卡可保存 PNG，报告可分享或复制。

## V3.1 改动

- 三层原创 SVG 符号缓慢漂浮、旋转，机器人循环呼吸、眨眼和悬浮，光束、光晕循环运动；作答时降低背景强度。
- 统一手机排版，作答界面只保留标题、一句目标、时间和必要数字；评分细节移入报告折叠项。
- 首次进入、每关开始和最终报告前播放约 1.22 秒的街机转场：大号关卡编号、斜切色带、进度条和短暂停顿。转场结束才启动观察和作答计时。
- 按钮、数字输入、记忆点选、指令队列、地图移动与碰撞、报告分数均有动效。装饰不拦截点击；支持 `prefers-reduced-motion`，降级时关闭运动并缩短转场至约 0.3 秒。
- 纯本地 `index.html` + `v31.css` + `questions.js`，经典脚本加载，保留双击打开和 `start.sh`。仅系统字体、原创 SVG / Canvas / CSS，无运行时外部依赖。

## 随机题库

每项使用约束生成器，组合数均远超 20 套；每次新开局重新生成，局内心算表达式和筛选数据包不重复。记忆闪烁允许原题难度所需的重复位置，逆序任务固定包含一次非相邻重复。生成后校验运算答案、序列约束、地图连通性、路径合法性和筛选目标数；恢复存档也先校验题目数据。

| 关卡 | 保留的难度约束 |
|---|---|
| 心算 | 3 题 / 30 秒；两位数乘一位数、两位数加法、整除 |
| 记忆 | 6 个不同位置，650ms 间隔，25 秒作答 |
| 导航 | 7×6 地图，11 步路线及最短路，7–10 次转向，5 秒观察 / 45 秒作答 |
| 编程 | 7×5 地图，电池在路线第 3 步，经电池最优 10 条指令，4–7 次转向，队列上限 14 / 65 秒 |
| 筛选 | 15 项 / 35 秒；随机颜色、形状、奇偶和验证状态；5 个目标、5 个单属性干扰和5个多属性干扰 |
| 紧急供电 | 3 题 / 45 秒；两位数乘两位数、括号减法乘法、整除加乘法 |
| 恢复记忆 | 8 格逆序，7 个不同位置，480ms 间隔，30 秒作答 |
| 终极导航 | 8×8 地图，20 步无重复格路线，14–18 次转向，最短路 14–18 步，5 秒观察 / 50 秒作答 |

地图先生成合法路线，再放置不占路线的障碍，以 BFS 校验最优步数；限制搜索次数并重试。评分仍按本局指定路线或最优指令数计算，公式和满分条件不变。随机化降低背题收益，离线客户端仍可被开发者工具读取答案。

## V3.1 验证

Chromium 390×844 触屏模拟，使用真实观察时长完整跑通首页、首次加载、8 关及逐关转场、自动最终报告：全部独立正确作答得到 100/S。10 次加载均约 1.22 秒；首页和各作答页无水平或垂直溢出，全部作答按钮在视口内；无 JS 报错和外部请求。报告保留 6 项复盘，PNG 可导出。

评分函数与原版逐字比较一致；验证记忆 3/6 = 50、导航多走两步 = 87、导航一次碰撞 = 82、编程最优 = 100 / 12 条指令 = 95 / 碰撞 = 60、筛选误选 = 60、心算部分分 = 33、提示 100→70 / 依赖8、接管 100→0 / 依赖20、超时不算极限通过、中断0分。验证随机题目刷新恢复、旧存档、V1 键保留、减少动态效果和 `file://` 直接打开。

题库自动检查 1,000 局，八项分别产生至少 20 套不同题目，并拒绝 12 类损坏题目；开发时另做了 10,000 局生成校验。截图和机器验证结果保存在 `/workspace/humanity-test-shots/`。复现：

```sh
node tests/questions.test.cjs
./start.sh 8876
# 另一个终端，使用已安装的 Playwright 和 Chromium（仅测试需要）：

CHROMIUM_PATH=/path/to/chrome node tests/browser.cjs
```

可通过 `TEST_URL`、`SHOTS_DIR` 自定义测试地址和截图目录。用户提供的 Makefile 原样保留并提交，支持 `make dev` 和 `make sg`。未进行真实手机硬件性能测试或人群难度校准；60fps 为优化目标，非设备实测保证。
